# 网络并发

## 引言

本文不适用于对并发有初步了解的读者。

## 并发模型

* 每个连接一个进程 (Process-per-Connection): 这是早期服务器（如 Apache 的 prefork 模式）采用的经典模型。每个客户端连接都会 `fork` 一个新的进程来处理。这种方式提供了极佳的隔离性，一个进程的崩溃不会影响其他进程。然而，创建进程的开销巨大，内存消耗和进程间上下文切换的成本使其无法应对大规模并发 。  &#x20;
*   每个连接一个线程 (Thread-per-Connection): 这是对进程模型的改进，每个连接生成一个新线程。线程比进程更轻量级，共享相同的内存空间，降低了创建和上下文切换的开销。但当连接数达到数千甚至数万时，线程切换的成本依然高昂，并且会引入线程同步的复杂性 。

    > 这是 Tomcat 传统的 BIO 连接器所采用的模型。  &#x20;

    >
    > 核心模型：它采用了基于Java NIO的I/O多路复用技术。其内部由少量专门的Poller线程和一个Worker线程池组成。
    >
    > * Poller线程：数量很少（通常每个CPU核心一个），它们负责循环监听所有连接，检查哪些连接上有数据到达（“I/O事件就绪”）。
    > * Worker线程池：当Poller线程发现一个连接有数据可读时，它会从这个线程池中取出一个Worker线程来处理该请求。请求处理完毕后，Worker线程会归还到池中，而不是被销毁。
    >
    >
* 事件驱动架构 (Event-Driven Architecture): 这种架构通常使用单个或少量线程，结合 I/O 多路复用技术来处理成千上万的并发连接。它通过一个事件循环 (Event Loop) 来响应 I/O 事件，从而避免了为每个连接创建线程或进程的开销，极大地减少了内存占用和上下文切换 。这是 Nginx 和 Node.js/libuv 成功的关键。
