# 分布式是什么？微服务是什么？

## 什么是分布式系统？

简单来说，**分布式系统**是指将一个原本运行在单个计算机上的应用程序或系统，拆分成多个独立的组件，并将这些组件部署在多台不同的计算机上，通过网络相互通信和协作，共同完成任务。

想象一下，一个传统的电商网站可能所有的功能（用户管理、商品展示、订单处理、支付等）都运行在同一台服务器上。当用户量增加时，这台服务器可能会不堪重负。

而一个分布式电商系统可能会将用户管理、商品展示、订单处理和支付等功能分别部署在不同的服务器上。当某个功能需要更多资源时，可以单独扩展相应的服务器，而不会影响其他功能。

**分布式系统的核心特点：**

* **组件分布在多台计算机上:** 这是最主要的特征。
* **通过网络通信:** 各个组件之间需要通过网络进行数据交换和协调。
* **协同工作:** 这些独立的组件共同完成整个系统的功能。
* **更高的可用性和容错性:** 如果一台服务器发生故障，其他服务器仍然可以继续工作，从而提高系统的整体可用性。
* **更好的可伸缩性:** 可以根据需求独立地扩展各个组件的资源。

## 什么是微服务？

**微服务**是一种特定的软件架构风格，它将一个大型的应用程序分解为一组小型、独立的服务。每个服务都运行在自己的进程中，并使用轻量级的通信机制（通常是基于 HTTP 的 RESTful API 或消息队列）与其他服务进行交互。

**微服务的核心特点：**

* **单一职责:** 每个微服务都专注于完成一个特定的业务功能。
* **独立部署:** 每个微服务都可以独立地进行开发、测试、部署和扩展，而不会影响其他服务。
* **技术多样性:** 不同的微服务可以使用不同的编程语言、框架和技术栈。
* **自治性:** 每个微服务都拥有自己的数据库和数据管理方式。
* **通过轻量级机制通信:** 通常使用 RESTful API 或消息队列进行通信。

## 分布式 VS 微服务

* **分布式系统是一个更广泛的概念:** 它描述了将应用程序的组件分布在多台计算机上的整体架构思想。
* **微服务是实现分布式系统的一种常见且流行的架构风格。**

## 分布式和微服务的关系

微服务架构本质上是一种构建分布式系统的方式。通过将应用程序拆分成小的、独立的服务，并将这些服务部署在不同的服务器上，就构成了一个分布式系统。

**分布式系统不一定非要使用微服务来实现。** 还有其他的分布式架构模式，例如：

* **单体应用 + 分布式数据库:** 整个应用程序仍然是一个单体，但其数据存储在多个数据库服务器上。
* **面向服务的架构 (SOA):** 类似于微服务，但服务可能更大、更复杂，且通信协议可能更多样化（例如 SOAP）。
* **网格计算:** 将大量的计算资源分布在不同的计算机上，用于解决复杂的计算问题。

[Moleculer](broken-reference)、NestJS、Fastify 等更偏向于构建微服务架构，因为微服务目前是构建可伸缩、高可用分布式系统的流行选择。但是，请记住，分布式系统是一个更广泛的概念，微服务只是实现它的一种方式。
