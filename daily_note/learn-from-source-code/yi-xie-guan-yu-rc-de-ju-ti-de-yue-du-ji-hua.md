## 五、解决性能问题

解决高并发下性能的问题。

首先，将单机的性能开发到我们认为的极限（最后不修改语言，迁移到C/C++上，不可能达到目前市场上的性能极限），所谓我们认为的极限，一方面架构已经合理（不使用Nodejs的架构，单线程异步的模式），另一方面一台单独的机器4G8核，能够处理的并发量在10s内达到数千（意思是一定要上千，至于是几千，尽力而为吧）。

其次，在不做容灾的情况下，将数万的并发的高性能解决掉。（彼时，在现有的处理能力下，使用多台4G8核的OS，搭建一个微服务+分布式系统）

所谓的高性能，目前在没有做可行性分析的情况下，暂定为**10s将发消息的业务流**处理完。
