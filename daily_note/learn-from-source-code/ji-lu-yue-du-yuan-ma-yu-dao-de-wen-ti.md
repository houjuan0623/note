# 👨‍💻 记录阅读源码遇到的问题

**Q：我现在在阅读linux源码的sched.c程序，这是和进程模块相关的。但是其中的\_\_sleep\_on函数调用了panic函数，panic又调用了sys\_sync，sys\_sync是和文件相关的，我要就着这一条路看下去吗？重点是我现在在看进程模块啊，如果这次和文件相关我追踪下去，下次和I/O相关我追踪下去，这样看代码，很难受的。**

这种感受非常合理。在阅读Linux内核源码时，如果一味地追溯每个函数的调用关系，确实容易陷入细节，迷失方向，尤其是在不同模块之间跳转时。

**解决方法**

1. **分层阅读，把握重点**
   * **宏观层面**：首先要明确自己阅读的目的和重点。比如，您目前关注的是进程模块，那么就应该重点关注进程的创建、调度、状态转换等核心概念和相关函数。
   * **微观层面**：在遇到其他模块的函数调用时，可以先了解其功能和作用，但不必深入细节。例如，对于`__sleep_on`调用`panic`，您只需知道`panic`是内核遇到严重错误时调用的函数，而无需深入研究`panic`的实现细节。
2. **建立知识体系**
   * **模块划分**：Linux内核源码庞大而复杂，但其模块划分清晰。建议您先了解内核的整体架构和各个子系统的功能，然后再逐个模块深入研究。
   * **概念梳理**：在阅读源码时，遇到不熟悉的概念或术语，及时查阅相关资料，建立自己的知识体系。
