# someTips

关于指令：cmpl %%ecx,\_current

Q：内联汇编中，为什么寄存器名称前有两个%？

A：

在GCC内联汇编中，`%%ecx` 和 `_current` 的写法具有特定的含义：

%%ecx

* **寄存器:** `%` 符号表示这是一个寄存器操作数。
* **转义:** 内联汇编中的寄存器名前需要加两个 `%` 符号，这是为了将其与C/C++变量区分开来。

因此，`%%ecx` 表示汇编指令中要使用的 `ecx` 寄存器。

Q：内联汇编中，为什么变量前有个\_？

A：

\_current

* **全局符号:** 在 C 语言中，以下划线开头的标识符通常表示全局变量或函数。在 Linux 0.12 的源码中，`current` 是一个全局变量，它指向当前正在运行的进程的 `task_struct` 结构体。
* **汇编与 C 语言的链接:** 在 Linux 0.12 中，内核代码由 C 语言和汇编语言混合编写。为了在汇编代码中引用 C 语言定义的全局变量，需要在变量名前加上下划线。这是因为 C 编译器在编译时会对全局变量名进行一些修改（通常是在前面加上下划线），以避免与其他符号冲突。

```c
#define switch_to(n) {\
struct {long a,b;} __tmp; \
__asm__("cmpl %%ecx,_current\n\t" \
  "je 1f\n\t" \
  "movw %%dx,%1\n\t" \
  "xchgl %%ecx,_current\n\t" \
  "ljmp %0\n\t" \
  "cmpl %%ecx,_last_task_used_math\n\t" \
  "jne 1f\n\t" \
  "clts\n" \
  "1:" \
  ::"m" (*&__tmp.a),"m" (*&__tmp.b), \
  "d" (_TSS(n)),"c" ((long) task[n])); \
}
```

Q：这段代码中为什么作者直接将ecx中的值和current比较，作者怎么知道ecx中储存的是什么？

A：这是由调用约定和上下文决定的。

**调用约定：** 在Linux x86架构中，函数调用约定规定了参数传递的方式。通常情况下，第一个参数会通过`ecx`寄存器传递。在`switch_to`宏的调用中，第一个参数就是新进程的`task_struct`指针。

除了调用约定还有一种情况是：

**上下文：** `switch_to`宏是在进程切换的特定上下文中被调用的。在这个上下文中，调用者（通常是调度器）已经将新进程的`task_struct`指针加载到`ecx`寄存器中。

上面代码中作者之所以知道ecx中的值，也就是上下文决定的："c" ((long) task\[n]))&#x20;

* 获取编号为 `n` 的任务的 `task_struct` 指针。
* 将该指针强制转换为 `long` 类型。
* 将转换后的 `long` 类型值存储在 `ecx` 寄存器中。

Q：指令之间出现的 `:` 什么意思？比如上一个问题中列举的代码中的  `: :"m"`

A：

先来看下内联汇编的整体结构：

```c
__asm__ (
    汇编指令模板
    : 输出操作数列表
    : 输入操作数列表
    : 扰乱寄存器列表
);
```

* `__asm__`：关键字，用于告诉编译器这是一段内联汇编代码。
* `汇编指令模板`：包含一系列汇编指令，用双引号括起来。
* `输出操作数列表`：以冒号分隔，列出内联汇编修改的 C 变量，以及对应的操作数约束。
* `输入操作数列表`：以冒号分隔，列出内联汇编读取的 C 变量，以及对应的操作数约束。
* `扰乱寄存器列表`：以冒号分隔，列出内联汇编中使用的寄存器，以便编译器在前后进行必要的保存和恢复。

**下面就输出操作数列表举例：**

输出操作数列表以冒号`:`分隔，每个操作数由以下部分组成：

* **约束修饰符:**
  * `=`: 表示这是一个输出操作数，汇编代码会修改其值。
  * `+`: 表示这是一个读写操作数，汇编代码既会读取也会修改其值。
* **操作数约束:**
  * 用于指定操作数的类型、位置和访问方式。常见的约束有：
    * `r`: 寄存器操作数
    * `m`: 内存操作数
    * `i`: 立即数
    * `g`: 通用寄存器、内存或立即数
* **C/C++变量:**
  * 括号中是要修改的C/C++变量名。

例如：

```c
int result;
__asm__ volatile (
    "movl $10, %0"   // 将10移动到result变量
    : "=r" (result)  // result是输出操作数，约束为寄存器
);
```

在这个例子中，输出操作数列表为 `"=r" (result)`，表示：

* `=`: `result` 是输出操作数，会被汇编代码修改。
* `r`: `result` 的值会存储在寄存器中。
* `(result)`: 括号中的 `result` 是要修改的C变量名。

输出操作数列表的主要作用是：

1. **告诉编译器哪些C/C++变量会被汇编代码修改。** 这样编译器就能在汇编代码前后正确地生成代码，确保变量值的同步。
2. **指定汇编指令中操作数与C/C++变量的对应关系。** 这样编译器就能根据操作数约束，选择合适的寄存器或内存地址来存储变量的值，并生成正确的汇编指令。
