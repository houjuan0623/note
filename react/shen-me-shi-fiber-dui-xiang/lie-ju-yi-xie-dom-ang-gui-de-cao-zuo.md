# 列举一些DOM昂贵的操作

**昂贵的 DOM 操作：**

* **修改 DOM 节点的几何属性:** 比如改变元素的宽度、高度、位置等，都会触发重排。重排是指浏览器重新计算元素的几何尺寸和位置，以及页面布局。这是非常消耗性能的操作，尤其当涉及到大量元素时。
* **修改 DOM 节点样式:** 修改字体、颜色、背景等样式属性，通常会触发重绘。重绘是指浏览器重新绘制受影响的元素。虽然重绘的成本比重排低，但频繁的重绘仍然会影响性能。
* **添加或删除 DOM 节点:** 这些操作会改变 DOM 树的结构，因此也会触发重排。
* **读取某些样式属性:** 例如 `offsetTop`、`offsetLeft`、`offsetWidth`、`offsetHeight`、`scrollTop`、`scrollLeft`、`scrollWidth`、`scrollHeight`、`clientTop`、`clientLeft`、`clientWidth`、`clientHeight` 等。读取这些属性会强制浏览器刷新队列并执行所有挂起的样式更改，这可能会导致不必要的重排。

**相对不昂贵的 DOM 操作：**

* **修改 DOM 节点的内容:** 例如修改文本节点的值。 虽然这可能会导致重绘，但成本相对较低。
* **移动 DOM 节点 (使用 `transform`):** 使用 CSS `transform` 属性来移动 DOM 节点，可以避免触发重排。`transform` 属性的改变不会影响其他元素的布局，因此浏览器可以更高效地处理这些变化。
* **使用 `opacity` 和 `visibility` 改变元素的显示状态:** `opacity` 和 `visibility` 属性的改变不会触发重排。
* **批量修改 DOM:** 将多个 DOM 操作合并在一起执行，可以减少重排和重绘的次数，从而提高性能。 例如使用 `DocumentFragment` 创建多个节点，然后一次性添加到 DOM 中。
* **使用虚拟 DOM:** React 等框架使用虚拟 DOM 技术来最小化直接的 DOM 操作。虚拟 DOM 会先在内存中进行比较和计算，然后只更新实际需要改变的 DOM 节点，从而提高性能。
