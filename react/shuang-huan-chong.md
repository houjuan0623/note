# 双缓冲

React 的双缓存机制是一种用于优化渲染性能的技术，它类似于图形学中的双缓冲。

**核心概念**

* **两棵 Fiber 树:** React 内部维护两棵 Fiber 树：
  * **current Fiber 树:** 对应当前屏幕上显示的内容，相当于“前台缓冲区”。
  * **workInProgress Fiber 树:** 对应下一帧要更新的内容，相当于“后台缓冲区”。
* **构建和替换:** React 在 `workInProgress` Fiber 树上进行组件更新和渲染，完成后一次性替换 `current` Fiber 树，从而更新 UI。

**工作流程**

1. **触发更新:** 当组件状态或属性发生变化时，React 开始构建新的 `workInProgress` Fiber 树。
2. **构建 Fiber 树:** React 遍历组件树，将组件及其子组件转换为 Fiber 节点，并计算每个节点的状态和属性。
3. **提交更新:** 当 `workInProgress` Fiber 树构建完成后，React 将其替换为 `current` Fiber 树，并更新 DOM。

**优点**

* **避免部分渲染:** 传统的渲染方式会在更新过程中直接操作 DOM，可能导致页面出现闪烁或卡顿。双缓存机制将更新过程隐藏在内存中，最终一次性更新 DOM，避免了部分渲染带来的问题。
* **提高渲染效率:** 双缓存机制允许 React 在后台构建 Fiber 树，不会阻塞主线程，从而提高渲染效率和用户体验。
* **支持并发模式:** React 的并发模式允许组件渲染工作被中断和恢复，双缓存机制为并发模式提供了基础，可以更好地管理组件更新和渲染过程。

**缺点**

* **内存消耗:** 双缓存机制需要维护两棵 Fiber 树，会增加内存消耗，尤其是在处理大型应用时。
* **复杂性:** 双缓存机制的实现比较复杂，增加了 React 内部代码的复杂度。

**总结**

React 的双缓存机制是一种有效的渲染优化技术，它通过在内存中构建 Fiber 树，避免了部分渲染和主线程阻塞，提高了渲染效率和用户体验。但是，它也带来了一些内存消耗和复杂性方面的开销。
